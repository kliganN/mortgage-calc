# AGENTS.md — mortgage-calc

Калькулятор ипотеки. SPA без бэкенда: все расчёты в браузере. Полный утверждённый план — в [PLAN.md](./PLAN.md).

## Стек и структура
- **Стек:** Vite 8, React 19, TypeScript 7, Tailwind CSS 4 + shadcn/ui (пресет Nova, база radix), Zustand, Recharts, exceljs, lz-string, react-router 8, next-themes, Biome 2, Vitest 5.
- **Ядро расчётов** — `src/lib/calc/` (чистый TS без React, копейки как целые числа). UI-компоненты shadcn — `src/components/ui/` (генерируются CLI, линт для них отключён в `biome.json`).

## Команды
```bash
npm run dev        # дев-сервер (http://localhost:5173)
npm run build      # tsc -b && vite build → dist/
npm run preview    # предпросмотр продакшн-сборки
npm run lint       # biome check .
npm run format     # biome check --write .
npm test           # vitest run (тесты ядра src/**/*.test.ts)
npm run test:watch # vitest в watch-режиме
```
Проверка этапа: `npm run build && npm run lint && npm test` — все три должны проходить.

## Обязательные правила работы

### 1. MCP-серверы (использовать всегда, когда применимо)
- **context7** — актуальная документация библиотек/фреймворков. Перед использованием API любой библиотеки: `resolve-library-id` → `query-docs`. Не полагаться на память о версиях. Если недоступен — официальный сайт через firecrawl.
- **firecrawl** — парсинг страниц и поиск информации по сайтам (`firecrawl_search`, `firecrawl_scrape`, `firecrawl_map`). Использовать для внешних источников (ставки, требования банков, справочные данные).
- **codebase-memory-mcp** (skill `codebase-memory`) — индексация и структурные запросы по этому проекту. Правило: любой вопрос про связи символов — сначала граф, а не grep.
    - кто вызывает X / что вызывает X → `trace_path` (direction: `inbound`/`outbound`/`both`)
    - найти функцию/класс по имени → `search_graph` (не Glob/grep)
    - влияние правок после git-diff → `detect_changes`
    - обзор пакета/слоёв/циклов → `get_architecture`
    - Grep/Read — только когда известен конкретный файл/строка или ищется текст внутри строки кода.

### 2. Сабагенты — распределять задачи
- **general-purpose** — многошаговые задачи, поиск по коду, рефакторинг, исследовательская работа.
- **Explore** — read-only обзор: найти, где что лежит, без правок.
- **judge** — визуальная приёмка рендеров (pptx/docx/xlsx/pdf/poster/chart), только по готовым PNG.
Параллельные независимые задачи запускать одновременно в одном сообщении. Браузерную работу (Browser Use) не делегировать — выполнять в основном агенте.

### 3. Skills/plugins — вызывать подходящие под задачу
Перед реализацией проверять список доступных skills и вызывать релевантные через Skill tool, а не переизобретать подход:
- UI/вёрстка калькулятора — `ui-ux-pro-max`, `ui-styling`, `design-system`, проверка — `web-design-guidelines`.
- Тестирование веб-интерфейса в GUI — `browser-use:web-gui-tester`.
- Генерация документов (xlsx-графики платежей, pdf-отчёты, pptx-презентации) — `document-skills:xlsx` / `pdf` / `pptx`.
- Структурные вопросы по коду — `codebase-memory`.
- SEO-аудит и подготовка к публичному запуску — `seo-audit` (установлен в `/Users/kligann/.codex/skills/seo-audit/SKILL.md`, источник: `coreyhaines31/marketingskills`).

### 4. SEO и будущая публикация
- Пользователь одобрил текущий внешний вид. SEO-работы должны сохранять его; существенные изменения интерфейса согласовывать отдельно.
- Перед публикацией применять `seo-audit`: проверять доступность основного контента SPA для поисковых роботов, метаданные, canonical, robots.txt, sitemap.xml, структурированные данные, скорость и мобильную доступность. Проверять актуальные требования Google и Яндекса по официальным источникам.
- Домен и хостинг пока не выбраны: не подставлять выдуманный публичный адрес и не заявлять, что сайт уже индексируется. Подключение Google Search Console и Яндекс Вебмастера выполнять после выбора домена с доступом владельца.
- Для ипотечной тематики описывать методику расчёта и её ограничения, подтверждать финансовые утверждения источниками; не придумывать банковские ставки, экспертов и отзывы.
- Не обещать конкретные позиции в выдаче. Установка скилла сама по себе не оптимизирует сайт и не запускает фоновое продвижение; результаты оценивать по фактическим данным после публикации.

## Конвенции
- Новая документация и комментарии в коде — на русском языке (язык пользователя).
- Формулы ипотечного расчёта (аннуитет/дифференцированные платежи) сопровождать комментарием с источником формулы.
- Денежные расчёты — целые копейки (округление каждого платежа до копейки, как в банках); дробные числа только на выводе через `src/lib/format.ts` (Intl ru-RU).
- Биом форматирование — табы; сгенерированные shadcn-компоненты не править руками без необходимости.
- Внимание: TypeScript 7 — `baseUrl` в tsconfig удалён, использовать только `paths`; в vite.config.ts — `import.meta.dirname` вместо `__dirname`.
