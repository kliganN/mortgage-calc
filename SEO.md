# SEO и публикация

## Тестовый запуск на Timeweb Cloud: subnetwork.ru

Проверено 28 октября 2026 года. `subnetwork.ru` пока используется как тестовый домен. Индексацию не включаем: `VITE_SITE_URL` не добавлять либо оставить пустой в переменных приложения; также не задавать его в отслеживаемом Git файле `.env.production`. Непустое значение этой переменной в текущей реализации включает индексацию публичных страниц.

Настройки App Platform для текущей структуры репозитория, где `package.json` находится в корне:

| Поле | Значение |
| --- | --- |
| Тип | Frontend, React; постоянный SSR-сервер не требуется |
| Node.js | 24, последняя доступная версия этой ветки |
| Команда сборки | `npm run build` |
| Зависимости | Оставить пустым: это системные пакеты `apt`, а не npm-пакеты |
| Директория сборки | `dist`, относительно корня проекта |
| Путь до директории проекта | Оставить пустым: проект находится в корне репозитория |

Node.js 24 удовлетворяет ограничениям установленных зависимостей. В частности, текущий `react-router` требует Node.js >=22.22.0, Vite — ^20.19.0 или >=22.12.0. Поэтому Node.js 20 для этого проекта не подходит. Локальная проверка выполнена на Node.js 26.10.0; сборка именно в окружении Timeweb Node.js 24 подтверждается логами первого деплоя.

Timeweb устанавливает npm-зависимости из проекта перед сборкой. В Git должны присутствовать `package.json`, `package-lock.json`, `scripts/prerender.mjs` и исходники. Если в логах окажется, что не установлены инструменты сборки (`tsc`/`vite`), проверить, что не включено исключение devDependencies. Воспроизводимый вариант команды для такой ситуации: `npm ci --include=dev && npm run build`.

После успешной сборки:

1. Открыть технический домен и проверить калькулятор, помощь, ввод ставки, графики и отчёт.
2. В приложении открыть **Настройки → Настройки веб-сервера → Настроить**. Выключить **SPA Fallback**. Платформа должна использовать существующий `404.html` для неизвестных адресов. Проверить фактический HTTP-статус: нужен именно 404, а не 200.
3. Там же доступны редиректы типа `path`: `/` → `/calculator` и `/charts` → `/calculator`, код 301. Параметры запроса сохраняются автоматически, их не нужно вписывать в поля правил. После добавления проверить, что `/calculator` продолжает открываться без циклического перенаправления.
4. Проверить прямое открытие и обновление `/calculator`, `/about`, `/report`. Каждый адрес должен получать собственный HTML из соответствующего каталога. Если платформа приводит путь к виду `/about/`, этот вариант нужно согласовать с canonical перед окончательным публичным запуском; во время теста индексация закрыта.
5. В **Настройки → Домены → Редактировать** добавить `subnetwork.ru`. Если DNS обслуживается у другого провайдера, указать A-запись **из подсказки панели приложения**, не выдуманный IP. Дождаться применения DNS и выпуска бесплатного SSL-сертификата. Для привязки приложения не требуется переносить регистрацию домена.
6. Проверить `https://subnetwork.ru/calculator` и `/about`: в исходном HTML должен оставаться `noindex, follow`. Отсутствие `sitemap.xml` в тестовой сборке ожидаемо. Пока не отправлять сайт на индексацию и не добавлять sitemap в поисковые системы.

Дополнительный запрет на время теста можно задать через HTTP-заголовок в настройках веб-сервера: действие `set`, имя `X-Robots-Tag`, значение `noindex, follow`. Перед окончательным запуском этот тестовый заголовок необходимо удалить. `noindex` не ограничивает доступ людей к сайту и не является паролем.

**Nginx-фрагмент ниже не вставляется в App Platform.** Timeweb управляет Caddy самостоятельно, а настройки выполняются через панель. Поддержка собственного `Caddyfile` для frontend в документации не заявлена. Если при выключенном SPA Fallback прямые адреса не обслуживаются из нужных каталогов либо ошибка возвращает 200, нужно уточнить маршрутизацию в поддержке до включения индексации.

Когда будет выбран постоянный домен: добавить `VITE_SITE_URL=https://постоянный-домен` в переменные сборки, удалить тестовый `X-Robots-Tag`, пересобрать и выполнить проверки публичного выпуска ниже. Если постоянным станет `subnetwork.ru`, значением будет `https://subnetwork.ru`. Не задавать публичный адрес, пока тестовый режим ещё нужен.

## Что подготовлено

Сборка `npm run build` создаёт готовый HTML из тех же React-компонентов в `dist/`: калькулятор, помощь, отчёт, совместимые старые адреса и `404.html`. Постоянный Node-сервер не нужен. `dist-ssr/` используется только при сборке и не публикуется. Калькулятор и помощь гидратируются, сохраняя исходный HTML до загрузки интерактивности; отчёт монтируется заново, потому что зависит от текущих параметров и даты.

У страниц отдельные title и description. Добавлены Open Graph, canonical публичных страниц и JSON-LD `WebApplication` для калькулятора. Разметка описывает приложение без вымышленных рейтингов и отзывов; расширенный сниппет не гарантируется.

`/report` и неизвестные адреса получают `noindex, follow`. В браузере ссылки с параметром `s` также получают `noindex`; canonical калькулятора всегда ведёт на чистый `/calculator`. Статический хостинг отдаёт одинаковый исходный HTML для чистого адреса и `?s=…`: запрет для таких параметров появляется после JavaScript. Это управление индексацией, а не защита секретов. Не помещайте персональные данные в ссылки; URL могут попасть в журналы хостинга.

В справке уточнены методика ежемесячного округления, ограничения сравнения стратегий досрочного погашения и хранение параметров в URL.

## Перед публичным выпуском

1. Выбрать основной HTTPS-домен. Создать `.env.production` по `.env.example` и заполнить `VITE_SITE_URL` настоящим origin без пути и параметров. Допустим и одноимённый параметр окружения на платформе сборки.
2. Выполнить `npm run build`. Значение домена встраивается и в клиент, и в HTML. После его изменения нужна новая сборка.
3. Опубликовать **содержимое `dist/`**. Не публиковать исходники, `.env`, `node_modules` и `dist-ssr`.
4. Проверить, что `/calculator` и `/about` возвращают собственные HTML с HTTP 200. Не настраивать общий fallback на `index.html` для всех URL: неизвестный адрес должен получать `404.html` с HTTP 404, а не калькулятор с кодом 200.
5. Настроить постоянные редиректы `/` и `/charts` на `/calculator` с сохранением query-параметров. Нормализовать адреса с завершающим слешем, HTTPS и вариант домена с www/без www. Это настройки будущего хостинга, сейчас они не применены.
6. Убедиться, что canonical и `og:url` содержат выбранный домен, а `robots` публичных страниц — `index, follow`. Открыть `/robots.txt` и `/sitemap.xml`; sitemap содержит только `/calculator` и `/about`.
7. Подтвердить владение доменом в Google Search Console и Яндекс Вебмастере. Передать sitemap и проверить обе публичные страницы средствами проверки URL/рендеринга.
8. Проверить HTTPS, сжатие, кеширование ресурсов с хешем и обновление HTML. Измерить PageSpeed Insights и позже полевые Core Web Vitals. Размер чанка графиков пока превышает 500 КБ; ExcelJS загружается по запросу при экспорте.

**Без `VITE_SITE_URL` сборка намеренно содержит `noindex, follow` и не создаёт sitemap.** Это режим до публикации. robots.txt разрешает обход, чтобы робот мог прочитать noindex. Для публичного запуска заполнить домен и пересобрать сайт; не удалять запреты вручную из отдельных файлов.

## Пример маршрутизации Nginx

Фрагмент для размещения в корне домена внутри настроенного HTTPS `server`. Путь `root`, сертификаты и перенаправление HTTP выбираются при развёртывании. На других платформах нужны эквивалентные правила.

```nginx
location = / { return 301 /calculator$is_args$args; }
location = /charts { return 301 /calculator$is_args$args; }
location = /calculator/ { return 301 /calculator$is_args$args; }
location = /about/ { return 301 /about$is_args$args; }
location = /report/ { return 301 /report$is_args$args; }
location = /calculator { try_files /calculator/index.html =404; }
location = /about { try_files /about/index.html =404; }
location = /report { try_files /report/index.html =404; }
error_page 404 /404.html;
location = /404.html { internal; }
location / { try_files $uri =404; }
```

## Дальнейшая работа

Основной запрос страницы калькулятора — «ипотечный калькулятор с досрочным погашением». Помощь отвечает на вопросы о методике, точности, стратегиях и данных. Это начальная карта тем, а не результат исследования частотности. После запуска уточнить запросы по фактическим показам и переходам; не создавать массовые одинаковые страницы под города/банки.

До публикации владелец должен предоставить настоящие сведения об авторе/организации и контакт для обратной связи, если они будут размещаться на сайте. Не выдавать вычислительную модель за точный банковский график. Добавление аналитики или внешних сервисов потребует актуализировать описание обработки данных.

Текущий аудит выполнен локально: проверены исходный HTML сборки, JSON-LD, sitemap с временным тестовым origin, навигация, расчёт и метаданные в браузере. Тестовый origin не сохранён в настройках проекта. Публичные позиции, индексация, настройки хостинга, Rich Results Test и полевые Core Web Vitals пока не проверялись — сайт не опубликован.
